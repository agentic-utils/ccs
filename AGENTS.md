# CCS - Coding CLI Sessions

## Overview

CLI tool to launch, watch, search and resume coding CLI sessions (Claude Code and Codex) using a bubbletea TUI.

## Development

### Build & Test

```bash
go build
go test -v -cover ./...
```

### Test Coverage

- **Target**: 60%+ statement coverage
- **Current**: ~69%
- All new features must include tests
- Break logic into testable functions when possible
- Refactor for testability (e.g., use variables instead of functions for dependency injection)

### Run locally

```bash
./ccs                    # search recent (60 days, <1GB files)
./ccs <query>            # search with initial query
./ccs --max-age=7        # last 7 days only
./ccs --all              # include everything, headless runs too
./ccs -- --plan          # pass flags to claude
./ccs link status        # what opens ccs://session/<name> links (ccs link install sets it up)
./ccs prune --dry-run    # preview lossless size reduction of large files
CCS_CPUPROFILE=cpu.out ./ccs   # record a CPU profile of the whole run (or ^X R to start/stop one, saved beside the update log); go tool pprof -top cpu.out
```

## Release Process

Merging to `main` releases automatically: `.github/workflows/ci.yaml` runs tests, bumps and pushes the tag from the conventional-commit prefixes (`feat:` minor, `fix:`/other patch, breaking-change major), then GoReleaser publishes and updates the Homebrew tap. Never tag by hand; `version` in `main.go` is injected at build time.

Turn on auto-merge as soon as a PR is opened: `gh pr merge <n> --auto --merge` (a merge commit, never squash, never `--admin`). The `main: tests must pass` ruleset requires the `test` check, so GitHub merges it once CI is green, without waiting to be asked; direct pushes to `main` are refused.

Each release's `checksums.txt` is signed by `.github/sign-release.sh` (GoReleaser's `signs`) with `RELEASE_SIGNING_KEY`, a secret of the `release` environment, whose deployment branch policy allows only `main`; ccs refuses to update to a release without a valid `checksums.txt.sig` against the public key in `internal/selfupdate` (`selfupdate.ReleaseKey`). A release job that can't sign fails rather than publishing unsigned. Rotating the key: generate a new one, ship a ccs release with both public keys trusted, then switch the secret; a ccs with only the old key can't update past the switch, so keep the old one until most users have updated.

If a merge's push event is lost and no release runs, start it by hand: `gh workflow run CI --ref main`.

Install the release locally: `brew update && brew upgrade ccs`.

## Architecture

`main.go` at the root holds only `version` (set at build time by `-X main.version`) and `main()`, which calls `app.Main(version)`, so `go install github.com/agentic-utils/ccs@latest` stays a one-liner. The rest is under `internal/`, being split into packages by area. Each package imports only those listed before it:

- `internal/state` - where ccs keeps its files and logs: `SettingsPath`, `MarksPath`, `UpdateLogPath`, `ActivityLogPath`, `LogUpdate`, `LogActivity`, `AppendLog`, and `Version`, the running release (set by `app.Main`, read everywhere)
- `internal/proc` - external commands with deadlines (`RunBounded`, `RunCommand`, `RunCommandIn`, `ErrTimedOut`) and process lookups (`PidAlive`, `ProcessStartTimes`, `PsAll`, `PsTree`, `TtyOf`, `SignalPID`, `ShellQuote`, `ShellSafe`); the stubbable ones are vars, which tests swap
- `internal/transcript` - Claude Code and Codex transcripts as `Conversation`s: full and incremental parsing behind `ParseCache` (`ParseLine`, `ParseAppended`, `ParseCodexFile`), `GetConversations`, search text and the search rule (`QueryMatches`, `MatchRank`), background tasks and subagents as recorded, spawned sessions, PR links in gh output (`GhPRCall`, `GhOutputPRs`), messages between sessions (`PeerRef`, `CcsNote`), token figures and prices, and `ccs prune` (`RunPrune`, `PruneFile`). Its `TestMain` points the `state` paths and `CodexHome` at a temp folder
- `internal/sessions` - the sessions running on this machine: which are live and their status (`ScanSessions`, `ReadLiveSessions`, Codex's from its processes and rollouts, `LiveCodexSessions`), messages over their sockets (`SendEnvelope`, `ReadSessionFile`, `PeerToken`) with delivery receipts (`ReceiptsCh`, `CloseInboxes`), their terminals (tmux, iTerm, T3 Code, background agents: `FocusSession`, `OpenResumeTab`, `HostOf`, `ListAgents`), `ccs launch` and `ccs close`, `ccs link`, and the open-sessions record. Its `TestMain` stubs every tab, process, Codex and link-handler hook, as `app`'s does
- `internal/github` - the user's PRs: lookups and status groups (`GhFetchPRs`, `GhPRBatch`, `PrInfo`), the PRs each session touched (`PrsOf`), `ccs watch` (`RunWatch`, `WatchPass`, `PrWatchState`, events in `PrEventsPath`), the owner registry (`ccs claim`, `ccs prs`: `RunClaim`, `RunPRs`) and nudges (`NudgeTick`). Its `TestMain` points the `state` paths at a temp folder and stubs `GhUser`
- `internal/selfupdate` - how ccs updates itself: the latest release (`LatestRelease`, `NewerVersion`), signed checksums (`SignedSums`, `ReleaseKey`), the upgraders (`ChooseUpgrader`, `Upgrader`: Homebrew or the binary in place), downloads (`Download`, `downloadTransport`) and release notes (`ReleaseChangelog`). Its `TestMain` points the logs at a temp folder
- `internal/app` (all `package app`, same directory) - everything else, split by area into the files below

- `cli.go` - `Main` (which sets `state.Version`), flags, `--help`
- `ui.go` - the bubbletea model: `initialModel`, `Init`, `Update`, `View`, the list, mouse handling, popups, key hints (`shortcuts`, `hints`), rename/delete/prune actions
- `parse.go` - the background refresh (`startRefresh`, `applyRefresh`) and list items from conversations (`buildItems`, `keepNewer`); parsing itself is `internal/transcript`
- `preview.go` - the conversation preview: `buildPreviewLines`, `renderBody`, markdown/tables/links, harness/teammate notes, time gutter, pinned date, search-hit jumps, the links popup
- `live.go` - the live tick (`liveCmd`, `applyLive`) and the resume, fork and focus commands; finding live sessions and their terminals is `internal/sessions`
- `chat.go` - the message box: sending (through `sessions.SendEnvelope`), the typing fallback, applying delivery receipts and showing delivery status
- `paste.go` - pasted images: ^V's clipboard image (`clipboardImage`, macOS) or a pasted or dropped path (`pastedImagePaths`: shell-escaped, quoted, `file://`; only when no prompt or popup has the keyboard, `takesImages`; from the search too, focusing the selected live session's box) is copied at once to `pastedDir()` (macOS deletes its screenshot temp files within moments; copies over 30 days old are swept) and shows as `[Image #N]` in the box (`attachImage`, `m.pasted` per session). The title is the `ccs launch` name (its launch folder among the workspace roots), else Codex's from `session_index.jsonl` (`transcript.codexThreadNames`). `transcript.GetConversations` adds `transcript.CodexRollouts()` to the same worker pool. Live: `sessions.CodexLiveSessions` (as `sessions.LiveCodexSessions`, stubbed in tests; one look shared for `transcript.CodexLiveTTL`) is merged into `sessions.ScanSessions` and never kept from an earlier scan (`liveSession.codex`): each `codex` TUI (a tty, no subcommand) and its thread, from `resume <id>`, else its `ccs launch` folder, else the latest rollout in its folder (`transcript.CodexProcCwd`, lsof) written since it started, since Codex doesn't hold the rollout open; status from the rollout's last turn event (`sessions.CodexStat`, also the fast tick's). A Codex row's grey line starts `codex`, the preview header has `Agent: ⬡ codex`, and `transcript.SearchTextOf` adds the kind so `codex` matches. ### Key Functions

- `getConversations(cutoff, maxSize)` - Loads conversations from `~/.claude/projects/` with filters
- `parseConversationFile(path, cutoff, maxSize)` - Parses JSONL files, skips by mtime/size
- `buildItems()` - Creates list items with searchable text
- `initialModel()` - Sets up bubbletea TUI
- `Update()` - Handles keyboard/mouse input, including delete confirmation
- `View()` - Renders the TUI with delete confirmation prompt
- `renderPreview()` - Renders conversation preview with highlights
- `handleMouse()` / `listLayout()` / `mouseLeak` - mouse reporting is on: the wheel scrolls whatever is under the pointer (conversation preview vs session list, by row from `listLayout`, which must match `View`), a click selects a list row; a mouse report that arrives split and reads as typed text is dropped before the search box (`mouseLeak`, plus `mouseFragment`: alt+[ and `[<;0-9Mm` bits within 150ms of a mouse event). Transcript text goes through `cleanText` before rendering, so stored colour codes or carriage returns can't reach the terminal
- `buildPreviewLines()` - with no search, the whole conversation; with a search, the first/last two messages plus matches with one message of context, gaps marked. `previewScroll` counts lines back from the newest message, so the preview opens (and any reset lands) at the latest message; `applyLive` shifts it by the lines added so a scrolled-back view stays still while new messages arrive
- `renderBody()` / `harnessNote()` - preview readability: each message is wrapped to the preview width with a hanging indent (`ansi.Wrap`, ANSI-aware), markdown rendered (bold, inline code, headings, bullets, `[text](url)` and bare addresses as underlined text plus a short grey address, both clickable OSC 8 terminal links (`hyperlink`, one per word so a wrapped link never stays open), tables as aligned columns via `renderTable`, widest columns cut with … to fit), messages shown in full up to `transcript.MaxMessageRunes`. Fenced code blocks over `maxCodeLines` collapse to `▸ lang · N lines` unless the search matches inside. Harness-injected user messages (`<task-notification>`, `<system-reminder>`, command output…) collapse to one dim `▸ tag · summary` line; messages from ccs/other sessions stay expanded
- `markFirst()` / `userRows()` / `renderTool()` - messages look as in Claude Code's terminal: `● ` before a reply, `❯ ` before what the user typed on a full-width grey row (`userBg`, set again after every code that ends a style inside it), a search match `▶` in place of either; `renderBody`'s two-column indent is the hanging indent. Tool calls (`conv.tools`, `transcript.ToolUse`, kept beside the messages and placed by `at`, as `peers` are, so counts, WHEN, done, search and `ccs mcp` ignore them) draw between messages as `● Bash(command)`, a command's lines verbatim and everything else one line (`transcript.toolArg`, `transcript.toolArgKeys`: a Write's content never reaches the preview); no results. A search hides them. `transcript.trackTools` notes Claude's, except SendMessage (a `To` message); `transcript.noteCodexTool` notes Codex's `item_completed` items (`Shell`, MCP, `Edit`, `WebSearch`). Messages carry no time. `renderPreview` puts the date and time of the top visible line at the right of the header's first line (`withWhen`, `humanWhen`: `Wed 28 Oct 21:51`; `stampAt`, from the `previewStamp`s `buildPreview` returns), and a new day after the first gets a dim row naming it. A finished turn ends with a dim `✻ 6m 53s · 21:51` (`turnEnd`; the agent's glyph), from the duration the agent recorded (`transcript.noteTurnEnd`: Claude Code's `turn_duration` lines, Codex's `task_complete`; never first to last message, which would count idle hours before a late notification), kept in `conv.tools` to stay in order; a session without those records has no such lines; harness notes stack without blank lines
- `headerSummary()` / `toggleHeader()` - ^X D or a click on the preview's header (a click on a link in it still opens the link) folds it to one line, `headerCollapsed`: topic, folder, agent if Codex, an API error, model, context %, PR counts, running tasks and subagents, size and messages, with the name capped so the counts stay on the line. One line by default (`settings.HeaderOpen` remembers otherwise); `initialModel` leaves it open and `main` applies the setting, so tests see the full header unless they fold it
- `linkAt()` / `openURL` / `carryStyles()` - ccs holds the mouse, so the terminal never sees a click on a link: a left click in the preview finds the OSC 8 link under the pointer in the rendered line and opens it (`open`/`xdg-open`, http(s) only). Wrapped lines are self-contained (`carryStyles` closes open styles/links at each line end and reopens them on the next), so an underline never bleeds across the screen

- `uiState` / `restore()` / `restoreEnv` - before the post-update restart, `uiState()` (screen name, search text and cursor position, selected SessionID, preview scroll, overlay snoozes) goes into `CCS_RESTORE_STATE` for the new process only; `main` reads it once, unsets it, and `restore()` puts the user back (a missing conversation is skipped). A new screen needs a case in `screenName()` and `restore()`
- Message box (`chat*`, `deliverMessage()`) - when the selected conversation is live, its preview gets a status line and a one-line message box. Moving the selection never focuses the box (`selectionMoved` clears focus); Enter on a live session opens its tab (`resumeCmd` focuses a live one), ^S or a click focuses the box, and Enter on the empty box opens the session too; Esc or clicking the search row returns to the search. Enter sends via `sendViaSocket` (the session file's `messagingSocketPath`: newline-delimited JSON, an `auth` line with the `sessions.PeerToken` from `<pid>.<sha256(socket path as written)>.key`, then a `user` message wrapped in `<cross-session-message from-name="the user, via ccs">`, starting with `transcript.CcsNote`, which tells the recipient it was typed by the user, not another Claude session, so it answers in its own conversation instead of messaging back; `peerParts` strips the note for the preview); only if the socket can't be reached at all (`sessions.ErrNotConnected`) does it type into the terminal instead (`typeIntoSession`: tmux `send-keys -l`, or iTerm `write text`; control characters refused). Never both. The socket gives no acknowledgement; the recipient logs a `queue-operation` enqueue the moment it arrives (`conv.peerQueued`), then hands it to Claude at once when idle (a user line prefixed "Another Claude session sent a message:") or at its next step when busy (an `attachment` of type `queued_command`, which `transcript.ParseLine` also reads, so mid-turn messages the user types show too). `checkDelivered` calls it delivered once it's in the conversation; a socket send not enqueued within `heldTimeout` (5s) shows a hedged warning that a bypass-permissions session may be holding it. Delivery receipts (`sessions.receiptInbox()` / `sessions.serveReceipts()` / `sessions.ParseReceipt()` / `applyReceipt()`): each socket message carries `msgV:1` and `from:"uds:<recipient's socket folder>/ccs-<pid>-inbox.sock"` (Claude Code only sends receipts to a `.sock` in the recipient's own socket folder, and checks the listener is the sending process); the session connects back with `{"type":"control","action":"peer_message_status","status":…,"orig_msg_id":…}` only when a message doesn't go straight in: held (shown as `⏸ held: approve it in <name>`, replacing the 5s guess), then delivered, denied or expired; refused (`expired` + `status_detail:"refused"`); or dropped (`drop_reason`, `dropped_msg_ids`). `sessions.SentMsgs` maps msg_id to session; `waitReceipt` blocks, so idle frames stay still. The inbox is removed when ccs exits (`sessions.CloseInboxes`), and inboxes of exited ccs processes are reaped (`sessions.reapInboxes`). Replies and idle notices sent to the inbox are ignored. Messages from ccs or other sessions (`transcript.PeerMessage`, kept even though marked meta) show in the preview under a `From <name>` header. While a live session is selected, `chatTickCmd` checks its transcript and busy/idle status every `chatFastRefresh` (250ms); an idle frame stays static, and only a busy session's working line changes: `workingLine`, at the left of the status row above the box, an animated glyph (`spinnerFrames`) and `Working…` in the agent's colour, then dim `(1m 4s · ↓ 2.5k tokens)`: the time since the status clock's start (`statusUpdatedAt`, which stays put through a turn's steps; Codex's task_started), and the output tokens of replies since then (`outputSince`, `conv.outputs`, finished replies only, so it runs behind Claude Code's live count). Claude Code's verb and tip aren't written anywhere ccs can read, so the word is fixed and there's no tip
- `transcript.noteSent()` / `transcript.noteReceived()` / `peerEnds()` / `peerLabels()` / `sessionLinks()` - messages between sessions, both ends: a `SendMessage` call becomes a `sent` Message (`To`, `Note` its summary; after the reply's text) drawn as `To <session>`; a cross-session message received keeps its sender's `from=` socket and `from-name`. Each is a `transcript.PeerRef` (`conv.peers`, its text's start as `transcript.peerKey`), so the other end is the session whose transcript holds the same text (`peerEnds` across all items), else the live session on its socket (`sessionAt`, the pid in `<pid>.sock`), else (received) the session titled as its from-name. A sent message found at the other end shows `✓ arrived`. The labels go into the preview through the drawn copy's `peerNotes` (part of `cachedPreview`'s key, so an arrival redraws it). ^O lists those sessions first (`→ to` / `← from`, `sessionLink`): Enter selects it in the list (`selectSession`: clears a search hiding it, expands its folder). `lastSaid` skips sent messages, so one sent after a question doesn't hide it
- `waitSignal()` / `waitQueue()` / `applyStats()` / `banner()` / `waitPopup()` - input-prompt overlay; read the invariant at the top of [the design doc](docs/design/input-prompt-overlay.md) before changing it. Statuses come from the live tick (`sessions.ScanSessions`, one read per session file) and the fast tick, and reach `chatStatus` only through `setStat`. `waiting` is Claude Code's status for a permission prompt or a question menu (`waitPrompt`, a magenta `●`); an `idle` session whose last message ends in `?` is `waitAsked` (a light magenta `●`: a guess, so it never gets the banner). A wait starts on entering `waiting` (or a new `statusUpdatedAt` while waiting) and ends on leaving it; `setStat` marks it `waitDue`, and its snooze (`snoozeRec`) ends with it. A session whose file is missing or unreadable keeps its last state while its pid is still the same process (`sessions.ScanSessions` gets the last scan, `lastScan`). Nothing pops up: waiting sessions sort first (`sortList`) and the title row counts menus and prompts (`waitingCount`, `^X W N waiting`); Ctrl+X W opens the overlay, which owns the keyboard, on the wait not yet seen first (`banner()`). The popups that can sit over it are `overPopups()`. It has its own input (`waitInput`, with `waitDrafts` per session; the main box likewise keeps `chatDrafts`, synced to the selection in `Update`) and transcript cache (`waitPreview`), so the main box's draft and the list's preview are untouched. Its keys are in its hint row; the fast tick follows its session while it's open (`chatTarget`). Enter on an empty box uses `focusCmd`, which never resumes a second claude. While it waits, the session's question is shown (`askLines`: the pending tool call `transcript.trackTools` keeps in `conv.pending` until its result; an AskUserQuestion's options numbered as claude shows them, else the tool a permission prompt is about), also in the bottom pane in place of the selected session's message box (`chatAsk`, counted in `chatRows`, at most half the screen, then a dim "… ^X W shows the rest"; the question and each option's description wrap in full rather than being cut; multi-select marked "pick any"; the box is hidden while it waits, `boxHidden`, since a message would be held until the menu is answered, so ^S and clicks don't focus it), with a status line under it saying where to answer (`waitingLine`); for a single single-choice question (`answerable`) a digit on the empty box answers it by pressing that key in its terminal (`typeKeys` without Enter). Permission prompts and multi-select or multi-question menus are only shown, never answered from ccs
- `autoFocusCmd()` / `applyAutoFocus()` / `userIdle` - auto-focus (^X A, off by default, saved in `settings`; the header says `auto-focus`): from each live tick, a session that starts waiting on a menu or prompt gets its tab or pane selected (`focusSession(pid, false)`: never `activate`, so iTerm isn't pulled in front of another app). Once per wait (`focusHandled`, by statusUpdatedAt, kept across restarts in `focusRecordPath`, so a restart doesn't switch to a question again but one that came up meanwhile is switched to); questions already waiting at startup or when ^X A turns it on are switched to as well; only after `autoFocusIdle` (2s) since the last key press (`userIdle`: CoreGraphics' seconds since a key-down, read through `osascript -l JavaScript`; the mouse doesn't count, it can't answer anything and is rarely still; unknown means never), so keystrokes meant elsewhere can't answer the menu; and not again until the question it switched to is answered (`focusHeld`). Each step goes once per wait to the activity log (`state.LogActivity`, `~/Library/Logs/ccs/activity.log` beside the update log; `noteFocus`): waiting, you're typing, switched, couldn't find its tab, holding on another, answered. Both logs share `state.AppendLog`, which rotates at 1MB to `.1`. Tests stub `userIdle` and `autoFocusTab`
- `acctKey()` / `acctPopup()` / `cswapActionCmd()` - account switcher (Ctrl+X U, or click the account email in the search row via `accountSpan()`), backed by the cswap CLI (`cswapPath`, absent means Ctrl+X U just says to install it): rows from `cswap list --json` (active marked, 5h/7d from `usage` else `lastGoodUsage`, `re-login` when `relogin_required`, as claude-dashboard). Digits or ↑↓ Enter run `cswap switch <n>`, `+` runs `cswap add`, both detached with a deadline, one at a time; the popup owns the keyboard and is overlaid last in `View`. After a change the list and the allowance/account are re-read (an in-flight allowance fetch is marked `allowanceStale` and repeated). Tests use a fake cswap on PATH; never run switch/add against real accounts in tests
- `github.RunWatch()` / `github.WatchPass()` / `github.PrWatchState` / `github.LoadPRWatchState()` - `ccs watch`: a foreground loop (`--interval` 3m, `--author` (default `github.GhUser`, the gh login, asked once at start; `github.defaultAuthor` fails loudly when gh can't say), `--owner` (default none: `github.searchPRs` drops `--owner`, so every owner's repos), `--once`), one at a time (`github.LockPRWatch`, flock on `pr-watch.lock` beside the settings). Each pass, REST through `github.GhRun` (stubbed in tests; never a GraphQL search, which hits RESOURCE_LIMITS_EXCEEDED): `gh search prs --state open`, and merged ones with `--merged-at ">=<max(watch start, now - mergedWindow)>"` (never a moving date window with a result cap, which makes old merges look new); per open PR (`github.PrDetails`, `github.prWatchParallel` at once) the pull, its head's check runs and statuses, and its reviews (each reviewer's latest approve, request-changes or dismissal). Checks are failing on any failed run or status, optional or not, so a PR GitHub calls mergeable (UNSTABLE) with a failed check is never `ready` or `needs_review`. Check runs, statuses and reviews are read on every page (`github.ghPaged`, 100 a page, at most `github.ghMaxPages`), so a failing check or an approval past the first 100 counts. For a PR whose checks pass and that isn't a draft, `github.unresolvedThreads` counts its unresolved review threads with a small GraphQL query a page, every page (REST doesn't say), into `Threads`, and the unresolved ones whose last comment isn't the operator's (`github.threadSelves`: `--author` and `--self-logins`) into `Unanswered` (thread id to that comment's id); not counted (checks not green) or a failed query keeps the last count (`threadsUnknown`), with no events. `ready()` and `needsReview()` need a counted zero (`threadsClear`); `needsReview()` is the one test of whether a PR awaits review. A PR gone from the open search and not in the merged one is asked directly (`github.prEndState`). The state (`pr-watch.json` beside the settings, atomic, `Updated` its freshness, read by `github.LoadPRWatchState`) is diffed and transitions appended to `github.PrEventsPath` (`pr-events.jsonl` beside the update log) and printed: `new`, `checks_failing`, `checks_passed`, `conflicts`, `threads_unresolved` (`unresolved`, when the count rises), `threads_resolved` (back to 0), `threads_unanswered` (`count`, `threads`, when `github.newReplies`: a thread new to `Unanswered` or with a new last comment), `ready`, `needs_review` (once per head, `AskedHead`), `merged`, `closed`. No state (or another author/owner) seeds: record everything, emit only `watch_started`. Blank search rows are dropped; mergeability `unknown` keeps the last answer; a PR whose details fail keeps its last state and emits nothing (activity log); a failed search changes nothing. Merged and closed PRs stay `github.mergedKeep` (7 days), longer than the search looks back `needs_review` is emitted only after `github.stillNeedsReview` asks GitHub again (`github.ReviewRecheck`, `github.PrDetails`), and sets `watchedPR.Awaiting`; `notNeeded` emits `review_not_needed` with `github.notNeededReason` when an awaiting PR stops awaiting (also just before merged/closed). The first run emits `needs_review` for PRs already awaiting. State version 2 (`github.PrWatchVersion`) keeps Awaiting; older state is migrated quietly (asked at its current head and still waiting = awaiting). `--review`, its old flags and `ccs review` are gone and exit 2 with `github.ReviewMoved` (the two-slack plugin's consumer posts review requests); the README documents the two review events as the stable consumer interface.
- `github.NudgeTick()` / `github.nudgeReasons()` / `github.nudgeText()` / `github.SendNudge` - after each successful pass (`github.afterPass`; `--no-nudge` turns it off): for each claimed open non-draft PR in the watcher's state, each owner `github.claimLive` says is running gets one message naming what's wrong: `threads` when `Unanswered` has a thread or reviewer comment it wasn't told of (`nudgeSent.Told`, kept across heads, so a push or an answered but unresolved thread never repeats it), `checks` (failing names), `conflicts`. `github.nudgeSent` per `github.nudgeKey` (PR and session) remembers the head and what was told at it; a new head starts afresh, a record of a PR no longer open is dropped; `nudges.json` beside the settings, under a flock and a unique temp file (`github.withNudgeState`). `github.SendNudge` checks the pid still runs that session (`sessions.ReadSessionFile`), then `sessions.SendEnvelope` with `github.nudgeSender` (`ccs watch`) and `github.NudgeNote` (an automatic notice, not the user: never `ccsSender`/`transcript.CcsNote`) and no return address, since the watcher serves no receipts; no typing fallback. A failure emits `nudge_failed`, is logged and isn't recorded, so the next pass tries again; a success emits `nudged`. Tests stub `github.SendNudge` and `github.LiveByPID`

### Demo

Colour, wording and fixes that don't change the layout don't count.

## Conventions

- Keys follow Claude Code's prompt: in a text box (the search, the message box, the overlay's box) every Ctrl letter edits text as it does there (^A/^E start/end, ^K/^U kill to end/start, ^W kill word, ^Y paste back, Alt+B/F words; `editKey` adds the ^Y the text box lacks). ccs's own actions are ^X chords, Claude Code's own pattern for app actions (`chordX`, `k = "^x <letter>"`; ^X ^W works as ^X W; an unknown chord does nothing, never edits text), with mnemonic letters: ^X A auto-focus, ^X D details, ^X E edit its name, ^X C collapse, ^X G group, ^X H headless, ^X I install updates automatically, ^X K kill (stop a background session, or a session in a terminal tab and close the tab), ^X N new session, ^X O open the coordinator, ^X P pin, ^X R record a CPU profile, ^X S snooze, ^X T table, ^X U user account, ^X W waiting, ^X X prune. Single keys that edit nothing stay single: ^S send, ^R refresh, ^L changelog log, ^O open a link, ^D delete, ^F fork, ? help on an empty search, Tab usage, PgUp/PgDn scroll, Alt+↑/↓ move a pinned session. A new action is a chord whose letter starts its word; when the letter is taken, pick the action's next clear word. Update the header hints, `shortcuts()`, `--help`, the README and the tests together

- Every interaction must be possible from the keyboard; the mouse (click, wheel) is only ever a shortcut for something a key already does

- Use conventional commits (feat:, fix:, docs:, etc.)
- Run tests before releasing
- Keep it simple: packages and files split by area as listed under Architecture; put new code in the package and file for its area, and never make a package import one listed after it
