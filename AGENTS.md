# CCS - Claude Code Search

## Overview

CLI tool to search and resume Claude Code conversations using a bubbletea TUI.

## Development

### Build & Test

```bash
go build
go test -v -cover
```

### Test Coverage

- **Target**: 60%+ statement coverage
- **Current**: ~69%
- All new features must include tests
- Break logic into testable functions when possible
- Refactor for testability (e.g., use variables instead of functions for dependency injection)

### Run locally

```bash
./ccs                    # search recent (60 days, <1GB files)
./ccs <query>            # search with initial query
./ccs --max-age=7        # last 7 days only
./ccs --all              # include everything
./ccs -- --plan          # pass flags to claude
./ccs prune --dry-run    # preview lossless size reduction of large files
```

## Release Process

Merging to `main` releases automatically: `.github/workflows/ci.yaml` runs tests, bumps and pushes the tag from the conventional-commit prefixes (`feat:` minor, `fix:`/other patch, breaking-change major), then GoReleaser publishes and updates the Homebrew tap. Never tag by hand; `version` in `main.go` is injected at build time.

Turn on auto-merge as soon as a PR is opened: `gh pr merge <n> --auto --merge` (a merge commit, never squash, never `--admin`). The `main: tests must pass` ruleset requires the `test` check, so GitHub merges it once CI is green, without waiting to be asked; direct pushes to `main` are refused.

If a merge's push event is lost and no release runs, start it by hand: `gh workflow run CI --ref main`.

Install the release locally: `brew update && brew upgrade ccs`.

## Architecture

One package, split by area (all `package main`, same directory):

- `main.go` - `main()`, flags, `--help`, `version`, and the bounded command runners (`runCommand`, `runBounded`)
- `ui.go` - the bubbletea model: `initialModel`, `Init`, `Update`, `View`, the list, mouse handling, popups, key hints (`shortcuts`, `hints`), rename/delete/prune actions
- `parse.go` - transcript types and parsing (`Conversation`, `RawMessage`, `parseLine`, `parseAppended`, `parseCache`), background refresh, search text, list formatting helpers
- `preview.go` - the conversation preview: `buildPreviewLines`, `renderBody`, markdown/tables/links, harness/teammate notes, time gutter, pinned date, search-hit jumps, the links popup
- `live.go` - live sessions (`~/.claude/sessions`), the live tick, resume/fork/focus in tmux or iTerm
- `chat.go` - the message box: socket send, delivery receipts, typing fallback, delivery status
- `wait.go` - the input-prompt overlay: live sessions waiting on the user, their queue, snoozes
- `update.go` - self-update (release check, brew/binary upgraders, `downloadTransport`, update log), changelog fetch and popups, restore-after-restart state
- `usage.go` - usage screen, allowance, keychain, cswap account switcher
- `prune.go` - `ccs prune` and the lossless pruning it shares with Ctrl+X X
- `tasks.go` - each session's background tasks: Bash run in the background, async subagents and Monitors, the list's ⧗ count and the preview's Tasks lines
- `prs.go` - each session's PRs: `pr-link` records, GitHub lookups, the PRS column and the preview's PR lines
- `mcp.go` - `ccs mcp`: a stdio MCP server (hand-rolled newline-delimited JSON-RPC: initialize, ping, tools/list, tools/call) with `search_sessions`, `list_sessions` and `read_session`. Each call rescans through `getConversations` (cheap after the first, via `parseCache`); stdout is the protocol stream, so nothing else may print to it
- `<area>_test.go` - tests live next to their code (`preview_test.go` for `preview.go`, and so on); a test that drives the UI goes with the feature it checks. Shared helpers (`TestMain`, `key`, `strip2`, `chatModel`, fake binaries and sockets) are in `helpers_test.go`
- `.goreleaser.yaml` - Release configuration
- `.github/workflows/test.yaml` - CI test workflow (reusable)
- `.github/workflows/ci.yaml` - On push to main: runs test.yaml, then tags and releases

### Dependencies

- `github.com/charmbracelet/bubbletea` - TUI framework
- `github.com/charmbracelet/bubbles/textinput` - Text input component
- `github.com/charmbracelet/lipgloss` - Styling

### Key Types

- `Conversation` - Parsed conversation with messages, timestamps, cwd
- `Message` - Single message (role, text, timestamp)
- `listItem` - Display item with conversation and search text
- `model` - Bubbletea application state (includes delete confirmation state)

### Key Functions

- `getConversations(cutoff, maxSize)` - Loads conversations from `~/.claude/projects/` with filters
- `parseConversationFile(path, cutoff, maxSize)` - Parses JSONL files, skips by mtime/size
- `buildItems()` - Creates list items with searchable text
- `initialModel()` - Sets up bubbletea TUI
- `Update()` - Handles keyboard/mouse input, including delete confirmation
- `View()` - Renders the TUI with delete confirmation prompt
- `renderPreview()` - Renders conversation preview with highlights
- `handleMouse()` / `listLayout()` / `mouseLeak` - mouse reporting is on: the wheel scrolls whatever is under the pointer (conversation preview vs session list, by row from `listLayout`, which must match `View`), a click selects a list row; a mouse report that arrives split and reads as typed text is dropped before the search box (`mouseLeak`, plus `mouseFragment`: alt+[ and `[<;0-9Mm` bits within 150ms of a mouse event). Transcript text goes through `cleanText` before rendering, so stored colour codes or carriage returns can't reach the terminal
- `buildPreviewLines()` - with no search, the whole conversation; with a search, the first/last two messages plus matches with one message of context, gaps marked. `previewScroll` counts lines back from the newest message, so the preview opens (and any reset lands) at the latest message; `applyLive` shifts it by the lines added so a scrolled-back view stays still while new messages arrive
- `renderBody()` / `harnessNote()` - preview readability: each message is wrapped to the preview width with a hanging indent (`ansi.Wrap`, ANSI-aware), markdown rendered (bold, inline code, headings, bullets, `[text](url)` and bare addresses as underlined text plus a short grey address, both clickable OSC 8 terminal links (`hyperlink`, one per word so a wrapped link never stays open), tables as aligned columns via `renderTable`, widest columns cut with … to fit), messages shown in full up to `maxMessageRunes`. Fenced code blocks over `maxCodeLines` collapse to `▸ lang · N lines` unless the search matches inside. Harness-injected user messages (`<task-notification>`, `<system-reminder>`, command output…) collapse to one dim `▸ tag · summary` line; messages from ccs/other sessions stay expanded
- `timeGutter()` - consecutive messages from one speaker share a `User` / `Claude` header (a new one on a speaker change, after a gap or harness line, and for each search match, marked `▶`); the date is a dim `── 2026-09-29 ──` row (`dateRow`), once per day, and `renderPreview` pins the top visible message's date in the header's last line unless its own row is already at the top; harness notes and messages from other sessions use the same time gutter, and consecutive notes stack without blank lines; every message starts with its time (`21:45`) and the text lines up after it
- `linkAt()` / `openURL` / `carryStyles()` - ccs holds the mouse, so the terminal never sees a click on a link: a left click in the preview finds the OSC 8 link under the pointer in the rendered line and opens it (`open`/`xdg-open`, http(s) only). Wrapped lines are self-contained (`carryStyles` closes open styles/links at each line end and reopens them on the next), so an underline never bleeds across the screen
- `visibleLinks()` / `linksPopup()` - Ctrl+O, the keyboard way to open links: collects the OSC 8 targets in the preview as drawn (top to bottom, each once; a link split word by word or across lines is joined back into its text), numbered in a popup that owns the keyboard (↑↓ ^P/N enter, 1-9, ^O/esc close; mouse ignored). No links in view says so in the header instead
- `teammateBlocks()` - messages from teammate agents (`<teammate-message teammate_id=… summary=…>`, several per message, optionally after "Another Claude session sent a message:") show one `From <id> · <summary or status>` block each; a JSON status report is unpacked (its `result`/`message` rendered as markdown), and a status with nothing to read (idle, shutdown) is one dim `▸ id · status` line
- `hitLinesIn()` / `jumpHit()` - with a search typed, Ctrl+] / Ctrl+\ put the next / previous hit at the top of the preview (wrapping; skips hits that share the final screen). Hits are the lines `buildPreviewLines` marks `▶` (never body text, which is indented), so nothing extra is cached; `renderPreview` adds `hit i/N` to the header's pinned-date line while searching
- `previewLines()` - Memoised `buildPreviewLines` for the selected conversation (rebuilt only when selection, query, message count or width changes), avoids per-frame rescans of huge conversations. It waits `previewDebounce` (150ms) after the selection changes (`noteSelection`, `selectedAt`; a `previewSettledMsg` redraws), so scrolling through the list draws only each preview's header and builds nothing for sessions passed on the way (a big one takes 100-200ms); the selected session's own PR lookup waits too. The first selection isn't delayed; tests set it to 0
- `queryMatches()` / `containsAll()` / `nameWords()` / `matchRank()` - the one search rule, shared by the list filter, HITS, the preview's matches, code-block expansion and `ccs mcp`: every word of the query starts a word in the text (`wordStartIndex`: "self" matches "self-revoke" and "selfish", not "itself"; no mid-word fragments), in any order within one part of the search text, i.e. the same message or the id/title/project (parts are joined by `searchSep`, so the list never shows a session with 0 HITS), or every word appears in the session's name with dashes/underscores read as spaces; `highlight` marks each word at word starts. Results rank by `matchRank` (named after the query, then the words together as a phrase via `hasPhrase`, then the rest), newest first within each; typing more narrows from the previous results only when the new query extends the old one (`HasPrefix`)
- `hitCount()` / `countHits()` - HITS column, shown only while a search is typed (`searching()`; `topicColWidth` takes the space back otherwise). Memoised per-query HITS count (messages containing every query word), keyed by SessionID, so `formatListItem` doesn't rescan every visible row each frame
- `sortList()` / `liveGroup()` - list order: sessions waiting on a menu or prompt first (amber `?`), then idle ones whose last message asks something (green `?`), then idle, busy, and those not open in claude; then search rank (`listItem.rank`), then newest. Statuses change on ticks, so `Update` re-sorts after every message, keeping the cursor on its session: the selection never changes without the user
- `prCmd()` / `ghPRBatch()` / `prInfo.status()` / `prLines()` / `prCell()` - a session's PRs are the `pr-link` records Claude Code writes whenever a gh command in it touches a PR (`Conversation.PRs`, github.com addresses only, validated by `prURL` since they go into a GraphQL query). `prCmd` runs from `Update`. The selected session's PRs not looked up yet get a request of their own (`prSelBusy`, `prSelAsked` stops retries until the next round) that never waits behind a round. Once a minute (`prNext`, after the previous round has drained) a round queues every PR not merged or closed of sessions live, active within `prScope` (7 days) or selected, `prBatch` per request (`prQueue`), `prParallel` in flight (`prRound`), each applied as it lands; merged/closed PRs are asked once. A PR GitHub returns null for is `GONE` ("not found"), never left "checking…"; without gh it says it needs gh. `ghPRBatch` asks about `prBatch` PRs per `gh api graphql` call (aliased fields) and reads the data even when gh exits non-zero over a missing PR. "Ready to merge" is GitHub's `mergeStateStatus` CLEAN/HAS_HOOKS/UNSTABLE on an open non-draft PR; `status()` groups the rest: needs you (conflicts, checks failing, changes requested, behind), waiting (checks running, review required, draft, unknown), then merged, closed. The PRS column counts open PRs (`✓` ready, `✗` needs you, plain waiting), in GitHub's colours: green ready, amber waiting, red to fix or closed, purple merged, grey draft or not looked up yet; the preview header lists open PRs in that order (at most `maxPRLines`) and one line counting merged/closed; ^O lists all of them first (`linksWithPRs`). No gh on PATH: `fetchPRs` is nil and nothing is looked up
- `noteCall()` / `noteResult()` / `noteEnds()` / `runningTasks()` / `taskLines()` - background tasks. A Bash, Agent or Monitor call (`conv.calls`) becomes a task (`conv.tasks`, `bgTask`) when its result starts with Claude Code's own words for it ("Command running in background", "Async agent", "Monitor started" with its expiry); anywhere else in a result it's only output mentioning them. A `<task-notification>` line marks one completed, failed or stopped by its tool-use id. Running = no end yet, the session open in claude, started after its current claude process (`lastScan`'s procStart: a resume or exit takes tasks with it unreported), and a monitor not past its expiry. Teammates ("Spawned") are left out: they never report an end. A task killed without a notification still counts as running (its output file ends "[killed]"; not read). The list shows `⧗N` in its own light blue (`taskColour`; on the sidebar's title row, before HITS while searching (which stay lined up at the edge), so the grey row below keeps the PRs to itself; the table after the title); the preview lists up to `maxTaskLines` with kind and age, then one line counting the ended
- `formatAgo()` - WHEN column: time since the last message (`now`, `5m ago` ... `1y ago`), recomputed each frame; replaces the absolute date in the list (full timestamps stay searchable and show per message in the preview)
- `formatTokens()` / `Conversation.ContextTokens` - CTX column: context size as of the last reply (input + cache reads + cache writes from its `usage`; zero-usage placeholder replies skipped)
- `contextWindow()` / `ctxColour()` - CTX column traffic light (green/yellow/amber/red/flashing, thresholds scaled to a 200k or 1M window inferred from the model, or proven 1M by a context over 200k)
- `Conversation.ActiveModel` / `shortModel()` - the model in use: the last reply's `message.model`, or a later `/model` switch parsed from its logged `Set model to …` output (`Model1M` when it names a 1M-context model). MODEL list column shows it short (`opus 5.5 1M`); the preview shows it exactly, noting a switch since the last reply
- `sessionStats()` / `tokenUsage.effective()` - preview header: model, context of window, summed usage (one reply spans several lines with the same `message.id`; counted once), effective tokens (1x input, 1.25x 5m write, 2x 1h write, 0.1x read, 5x output) and cost at `pricePerMTok`; the last surfaced API error (`isApiErrorMessage`) until a later successful reply, also shown as a red `!` in the list
- `formatListItem()` - Formats a single list row; `●` live (green when idle, amber while busy; an amber `?` instead when it waits on you, see the overlay) / `!` API error are packed right into a 3-cell column (`colMarks`) just before the title, so titles stay aligned; `✎` trails a user-set name
- `readLiveSessions()` / `liveSessionPIDs()` - SessionIDs open in a running claude, from `~/.claude/sessions/<pid>.json` where the pid is alive and its start time (`ps lstart`, read in UTC) matches the file's `procStart` (UTC), so a recycled pid doesn't count. Files are checked per pid before mapping to sessions, so a stale leftover can't hide the live file
- `liveTick()` / `liveCmd()` / `applyLive()` - every `liveInterval` (2s): re-read `~/.claude/sessions` and, for live (and just-exited) sessions, `parseAppended()` their transcripts; updated rows re-sort in place, keeping the cursor; `applyLive` re-matches and re-counts only changed rows (preview cache is keyed by SessionID+Size+query, so it rebuilds only if the selected conversation changed). A live session not in the list yet triggers an early full scan (`startRefresh(true)`, at most every 15s; early scans don't reschedule, so the one-minute chain stays single)
- `parseAppended()` / `consumeLines()` - incremental parse: seek to `parsedBytes` (end of the last complete line) and parse only appended lines. A line caught mid-write isn't applied, so parsing resumes at it; full reparse only if the file shrank (prune) or an unterminated last line *was* applied as a record (`tailApplied`). Search text stays identical to `searchTextOf` (which ends with the last timestamp): new messages swap that suffix and lowercase only the new part (`appendedSearchText`); anything else rebuilds. Live reads run in parallel with a per-tick deadline; a read still stuck from an earlier tick isn't restarted (`liveReads`)
- `Conversation.readAt` / `keepNewer()` - every parsed copy records when it was read from disk; between a full scan and the live tick the later read wins (in both directions). Size can't decide it: a prune legitimately shrinks a file
- `runBounded()` / `runCommand()` - every external command has a deadline (and `WaitDelay`, so an inherited pipe can't outlive it) and reports a timeout as `errTimedOut`. git/brew run detached (`Setsid`, `GIT_TERMINAL_PROMPT=0`, batch-mode ssh), so they can't prompt behind the TUI
- `resumeCmd()` - Enter/Ctrl+F run off the UI goroutine: fresh liveness check, then focus (`focusDoneMsg`), a new tab/window, or exec in place (`resumeDoneMsg`). `tabResult`: only a timeout counts as "may have opened" (reported, no second launch); any other failure (Automation denied, stale `$TMUX`) resumes in place, as does a cwd/arg that isn't `shellSafe` (backslash, control chars). One open at a time; a session opened in a tab stays live via `m.opened` for `openedGrace` until claude's own session file appears. tmux `-c` gets `#` escaped (tmux expands `#(cmd)` there)
- `refreshNote()` - header shows what the background refresh is doing: `refreshing…`, `refreshed just now` / `3m ago`, or `refresh failed, list from 3m ago`. Minute granularity and a static (non-blinking) cursor keep the idle frame identical, so bubbletea writes nothing and terminals don't show the tab as busy; don't add anything that changes every second while idle
- `refreshStalled()` - header shows "refresh stalled Nm" when a scan has run over 5 min (e.g. hung network mount); it can't be cancelled
- `refreshTick()` / `applyRefresh()` - Background re-scan every `refreshInterval` (1 min), keeping the cursor on the same conversation; skipped while a delete/prune/rename prompt is open, and dropped if `m.gen` moved (a delete/prune/rename happened while the scan ran); search text is built once at parse and shared through `parseCache`, so unchanged conversations cost nothing on refresh
- `parseCache` - Reuses parsed conversations whose file size+mtime are unchanged, so refreshes only reparse changed files
- `openResumeTab()` / `resumeInTmuxWindow()` / `resumeInITermTab()` - Opens the selected conversation in a new tmux window or iTerm tab (focus stays on ccs); falls back to exec-in-place elsewhere
- `recordOpen()` / `reopenCheckCmd()` / `reopenPopup()` / `reopenCmd()` - reopening after a restart: each live tick (once the last record has been read) writes the live SessionIDs with `bootID()` (Linux boot_id, else macOS `kern.boottime`) to `openRecordPath` when the set changes. At startup, a record from another boot offers its sessions that aren't open again and are still listed, in a popup that owns the keyboard (enter reopens all in new tabs via `openResumeTab`, skipping any open by then and stopping at the first failure; esc not now). Only works if a ccs was running before the restart
- `focusSession()` / `tmuxPaneForTTY()` - opening a live session (Enter on its empty message box): find its terminal by the claude pid's tty (`liveSessionPIDs()`) and select that tmux pane or iTerm tab instead of resuming a second copy
- Ctrl+F forks: `openResumeTab` / exec with `--fork-session`
- `latestRelease()` / `newerVersion()` / `chooseUpgrader()` / `upgrader` - Self-update: at startup and every `updateCheckInterval` (2 min; `updateCheckBackoff` 10 min after a failed check), read the newest tag from the `github.com/.../releases/latest` redirect (not the REST API, whose 60/h unauthenticated limit shared IPs exhaust). If newer, `upgrader.Prepare` starts the slow, side-effect-free part in the background (Homebrew: `git pull` of just the ccs tap + `brew fetch`; otherwise download + verify against `checksums.txt`) while a popup over the preview offers Enter = install and re-exec, Esc = later (for that version, this session). `Install` waits for an in-flight prepare, then: Homebrew kegs (`/Cellar/`) only ever `brew upgrade agentic-utils/tap/ccs` (never overwritten); `/nix/` notify only; anything else atomically renames the verified binary over the old. The header shows the current step and elapsed seconds (`updateProgress`). Keys are ignored for `updateKeyGrace` after the popup opens. `dev` builds never check
- `releaseChangelog()` / `parseChangelog()` / `changelogBlock()` - when an update is offered, the popup lists what changed in every release after the running version up to the new one (the `releases.atom` feed, not the REST API; it holds the latest 10 releases), commit subjects under each version, capped at `maxChangelogLines`. GoReleaser drops merge commits and hashes from the notes. A failed fetch is logged and the popup shows no list
- `notesPopup()` / `scrollNotes()` - Ctrl+L changelog, any time: every release (`releaseChangelog("0.0.0", …)`: the REST API's release list, one call per run, for the whole history; the Atom feed's latest 10 if the API fails; fetched in the background at startup through `downloadTransport`, so ^L opens instantly and a stalled GitHub address is skipped; a failure is logged to the update log and the popup offers enter to retry; never two fetches at once (`notesFetching`)), the installed version and newer ones marked; owns the keyboard (↑↓ ^P/N ^J/K, PgUp/PgDn, the wheel; ^L/esc close), stops at the end, and only offers ↑↓ when it doesn't fit
- `downloadTransport` / `dialTLSAnyAddr()` - every self-update download tries each address the host resolves to, with `addrAttemptTimeout` (5s) for TCP + TLS, moving on when one fails; failed addresses go last for the rest of the process. Each attempt is logged
- `preseedBrewCache()` / `seedFile()` - Homebrew installs: take the formula's URL and sha256 from `brew info --json=v2` and the path from `brew --cache`, download with `downloadTransport`, verify, and write atomically into brew's cache so `brew fetch`/`upgrade` find it there (brew verifies again). Any problem is logged and brew downloads as usual; nothing outside the cache is touched
- `logUpdate()` / `updateLogPath` - self-update log (`~/Library/Logs/ccs/update.log` on macOS, capped at 1MB): every git/brew command with full output, exit and duration (brew fetch/upgrade run with `HOMEBREW_CURL_VERBOSE=1`, so each address curl tried is visible), every download with the address it connected to, and each prepare/install outcome. A failed update's popup points at it
- `collectUsage()` / `usageView()` / `renderUsageChart()` - Usage screen (Tab), ported from claude-dashboard: every transcript (subagents included) modified in the last 12h, replies de-duplicated by `message.id` (else `requestId`), into 144 five-minute buckets: chart 1 uncached/5m write/1h write, chart 2 cache read/new input/cache miss (fresh input on a turn that read 0 from cache), chart 3 output; buckets merge to fit narrow terminals. Per-file records cached by size+mtime (`usageFiles`). SUMMARY: 12h totals, effective tokens 1h/12h, cache mix. Collected off the UI goroutine when the screen opens and on each 1-minute refresh while it's open
- `usageSummary()` / `usageView()` panels - below the charts, SUMMARY, CACHE MIX and ALLOWANCE sit in three equal columns across the screen, values right-aligned
- `allowanceSummary()` / `accountEmail()` - the search row shows the Claude account as cswap does, `email [organisation]` (`oauthAccount.emailAddress` and `organizationName` from `.claude.json`: one email can be in several organisations, and the allowance is the organisation's) and 5h/weekly % with the 5h reset; the allowance is fetched at startup and each minute. On the usage screen the search box and list-only shortcuts are hidden (`tab back  ^X U account  ^L changelog  ^C quit`, every key it has, so ? does nothing there)
- `fetchAllowance()` / `keychainRead` - ALLOWANCE panel: Claude Code's OAuth token read-only (`/usr/bin/security find-generic-password` for `keychainService()`, which hashes CLAUDE_CONFIG_DIR like Claude Code, else `.credentials.json`), then GET `api/oauth/usage` (`limits`: `session`, `weekly_all`). An expired/missing token or a 401 shows "open claude to refresh the allowance"; ccs never refreshes or writes the credential. At most once a minute, only while the usage screen is open
- `sidebarView()` / `sidebarRow()` / `table` - two layouts, ^X T switches (`table`; it and ^X G's `grouped` are saved to `settingsPath` on each toggle, `saveSettings`, and read at startup, `loadSettings`, so ccs reopens in the view it was left in; an update restart also carries them in `uiState`). The default is a sidebar (`sidebarWidth`: a quarter of the width, 30-48), two rows a session (`rowsPerItem`, which the mouse and scroll offset use): marks, title and HITS while searching, then a grey row of age · context · project with the PR cell on the right; beside it the preview (`paneWidth`), which fills the rows under the search and gains a `Size:` line in its header for the columns it lost; `table` is the full-width table above the preview. Anything sized to the preview uses `paneWidth`, never `m.width`, and the mouse tells list from preview by X as well as Y (`paneX`)
- `listRows()` / `listStart()` / `groupKey()` / `grouped` - the list as screen rows (`listRow`: part of a session, or a group header with item -1); both layouts, the mouse and the scrollbars go through them, never `cursor` arithmetic. ^X G groups by folder (`grouped`, kept in `uiState`): `groupKey` is the cwd with any `/.claude/worktrees/…` cut off, so worktrees join their repo; The list always has state sections (`stateSections`: waiting on you, asked you something, idle, busy, not open in claude; a family in its most urgent session's, `familyState`), each with a header and count. `sortList` sorts as usual, then stable-sorts by section and, with ^X G, by folder within it (`groupOf`), a group where its first session landed, so the one with a question comes first; a folder can appear in several sections. Headers aren't selectable
- `scrollThumb()` / `barCell()` / `withBar()` - scrollbars: the thumb's size is the share in view, its position where the view starts. The preview's messages keep their last column for it (wrapped to `paneWidth()-1`); the list's is the sidebar's divider, or the table rows' last column (`topicColWidth` leaves it). No bar when everything fits
- `headerLine()` - the title row never wraps (`listLayout` counts it as one row): on a narrow terminal hint pairs drop from the end, keeping help and quit, then the title is cut with …
- `shortcuts()` / `hints()` / `helpPopup()` - key hints everywhere use the compact labels (`keyEnter` enter, `keyTab` tab, `keyEsc` esc, `^S` for Ctrl+S; keys bold) via `hints()`. The header shows only the common keys; ? opens a popup of the keys that work right now, from `shortcuts()` (screen, selection, live or not, message box focus, a search typed, cswap installed; add new keys there with their condition). The popup owns the keyboard (?/Esc close, Ctrl+C quits) and is overlaid last
- `View()` / `viewScreen()` / `overlayCentre()` - `viewScreen` draws the current screen (list or usage); `View` then overlays popups (the update offer) centred on top, ANSI-aware so the screen stays visible around them. Screens never draw popups themselves, so any new screen gets them for free
- `uiState` / `restore()` / `restoreEnv` - before the post-update restart, `uiState()` (screen name, search text and cursor position, selected SessionID, preview scroll, overlay snoozes) goes into `CCS_RESTORE_STATE` for the new process only; `main` reads it once, unsets it, and `restore()` puts the user back (a missing conversation is skipped). A new screen needs a case in `screenName()` and `restore()`
- Message box (`chat*`, `deliverMessage()`) - when the selected conversation is live, its preview gets a status line and a one-line message box. Moving the selection never focuses the box (`selectionMoved` clears focus); Enter on a live session opens its tab (`resumeCmd` focuses a live one), ^S or a click focuses the box, and Enter on the empty box opens the session too; Esc or clicking the search row returns to the search. Enter sends via `sendViaSocket` (the session file's `messagingSocketPath`: newline-delimited JSON, an `auth` line with the `peerToken` from `<pid>.<sha256(socket path as written)>.key`, then a `user` message wrapped in `<cross-session-message from-name="the user, via ccs">`, starting with `ccsNote`, which tells the recipient it was typed by the user, not another Claude session, so it answers in its own conversation instead of messaging back; `peerParts` strips the note for the preview); only if the socket can't be reached at all (`errNotConnected`) does it type into the terminal instead (`typeIntoSession`: tmux `send-keys -l`, or iTerm `write text`; control characters refused). Never both. The socket gives no acknowledgement; the recipient logs a `queue-operation` enqueue the moment it arrives (`conv.peerQueued`), then hands it to Claude at once when idle (a user line prefixed "Another Claude session sent a message:") or at its next step when busy (an `attachment` of type `queued_command`, which `parseLine` also reads, so mid-turn messages the user types show too). `checkDelivered` calls it delivered once it's in the conversation; a socket send not enqueued within `heldTimeout` (5s) shows a hedged warning that a bypass-permissions session may be holding it. Delivery receipts (`receiptInbox()` / `serveReceipts()` / `parseReceipt()` / `applyReceipt()`): each socket message carries `msgV:1` and `from:"uds:<recipient's socket folder>/ccs-<pid>-inbox.sock"` (Claude Code only sends receipts to a `.sock` in the recipient's own socket folder, and checks the listener is the sending process); the session connects back with `{"type":"control","action":"peer_message_status","status":…,"orig_msg_id":…}` only when a message doesn't go straight in: held (shown as `⏸ held: approve it in <name>`, replacing the 5s guess), then delivered, denied or expired; refused (`expired` + `status_detail:"refused"`); or dropped (`drop_reason`, `dropped_msg_ids`). `sentMsgs` maps msg_id to session; `waitReceipt` blocks, so idle frames stay still. The inbox is removed when ccs exits (`closeInboxes`), and inboxes of exited ccs processes are reaped (`reapInboxes`). Replies and idle notices sent to the inbox are ignored. Messages from ccs or other sessions (`peerMessage`, kept even though marked meta) show in the preview under a `From <name>` header. While a live session is selected, `chatTickCmd` checks its transcript and busy/idle status every `chatFastRefresh` (250ms); an idle frame stays static, and `✻ working Ns` only ticks while busy
- `waitSignal()` / `waitQueue()` / `applyStats()` / `banner()` / `waitPopup()` - input-prompt overlay; read the invariant at the top of [the design doc](docs/design/input-prompt-overlay.md) before changing it. Statuses come from the live tick (`scanSessions`, one read per session file) and the fast tick, and reach `chatStatus` only through `setStat`. `waiting` is Claude Code's status for a permission prompt or a question menu (`waitPrompt`, a bright `?` in place of `●`); an `idle` session whose last message ends in `?` is `waitAsked` (a green `?`, the colour of idle: a guess, so it never gets the banner and sorts with idle). A wait starts on entering `waiting` (or a new `statusUpdatedAt` while waiting) and ends on leaving it; `setStat` marks it `waitDue`, and its snooze (`snoozeRec`) ends with it. A session whose file is missing or unreadable keeps its last state while its pid is still the same process (`scanSessions` gets the last scan, `lastScan`). Nothing pops up: waiting sessions sort first (`sortList`) and the title row counts menus and prompts (`waitingCount`, `^X W N waiting`); Ctrl+X W opens the overlay, which owns the keyboard, on the wait not yet seen first (`banner()`). The popups that can sit over it are `overPopups()`. It has its own input (`waitInput`, with `waitDrafts` per session; the main box likewise keeps `chatDrafts`, synced to the selection in `Update`) and transcript cache (`waitPreview`), so the main box's draft and the list's preview are untouched. Its keys are in its hint row; the fast tick follows its session while it's open (`chatTarget`). Enter on an empty box uses `focusCmd`, which never resumes a second claude. While it waits, the session's question is shown (`askLines`: the pending tool call `trackTools` keeps in `conv.pending` until its result; an AskUserQuestion's options numbered as claude shows them, else the tool a permission prompt is about), also in the bottom pane in place of the selected session's message box (`chatAsk`, counted in `chatRows`, at most half the screen, then a dim "… ^X W shows the rest"; the question and each option's description wrap in full rather than being cut; multi-select marked "pick any"; the box is hidden while it waits, `boxHidden`, since a message would be held until the menu is answered, so ^S and clicks don't focus it), with a status line under it saying where to answer (`waitingLine`); for a single single-choice question (`answerable`) a digit on the empty box answers it by pressing that key in its terminal (`typeKeys` without Enter). Permission prompts and multi-select or multi-question menus are only shown, never answered from ccs
- `autoFocusCmd()` / `applyAutoFocus()` / `userIdle` - auto-focus (^X A, off by default, saved in `settings`; the header says `auto-focus`): from each live tick, a session that starts waiting on a menu or prompt gets its tab or pane selected (`focusSession(pid, false)`: never `activate`, so iTerm isn't pulled in front of another app). Once per wait (`focusHandled`, by statusUpdatedAt, kept across restarts in `focusRecordPath`, so a restart doesn't switch to a question again but one that came up meanwhile is switched to); questions already waiting at startup or when ^X A turns it on are switched to as well; only after `autoFocusIdle` (2s) since the last key press (`userIdle`: CoreGraphics' seconds since a key-down, read through `osascript -l JavaScript`; the mouse doesn't count, it can't answer anything and is rarely still; unknown means never), so keystrokes meant elsewhere can't answer the menu; and not again until the question it switched to is answered (`focusHeld`). Each step goes once per wait to the activity log (`logActivity`, `~/Library/Logs/ccs/activity.log` beside the update log; `noteFocus`): waiting, you're typing, switched, couldn't find its tab, holding on another, answered. Both logs share `appendLog`, which rotates at 1MB to `.1`. Tests stub `userIdle` and `autoFocusTab`
- `acctKey()` / `acctPopup()` / `cswapActionCmd()` - account switcher (Ctrl+X U, or click the account email in the search row via `accountSpan()`), backed by the cswap CLI (`cswapPath`, absent means Ctrl+X U just says to install it): rows from `cswap list --json` (active marked, 5h/7d from `usage` else `lastGoodUsage`, `re-login` when `relogin_required`, as claude-dashboard). Digits or ↑↓ Enter run `cswap switch <n>`, `+` runs `cswap add`, both detached with a deadline, one at a time; the popup owns the keyboard and is overlaid last in `View`. After a change the list and the allowance/account are re-read (an in-flight allowance fetch is marked `allowanceStale` and repeated). Tests use a fake cswap on PATH; never run switch/add against real accounts in tests
- `deleteConversation()` - Removes conversation file and updates UI state
- `pruneConversation()` - Prunes the selected conversation in place (Ctrl+X X) and refreshes its size
- `getTopic()` - Title, else first real user message (skips tag-wrapped harness text, shows `/cmd` or `! cmd` for command-only sessions), else session id
- `refreshNow()` - Ctrl+R: the minute's work now: a session rescan (`startRefresh(true)`, not if one is running), a PR round (`prNext` reset), the allowance and a ccs update check
- `renameConversation()` / `appendLine()` - Ctrl+X E (edit its name) rename: appends a `custom-title` line like `/rename`; refused on live sessions since a running claude re-appends its own title
- `Conversation.Spawned` - first user line has `entrypoint: sdk-cli` or a `teamName`: a candidate for nesting under the session that started it. No mark of its own: sdk-cli is also what an app (the desktop app, an editor) starts a session you type in with
- `nestFamilies()` / `spawnParent()` / `findSpawnParent()` / `spawnCmd` - a spawned session sits under the session that started it, marked `└` (`listItem.depth`). Claude Code records no parent, so `trackTools` keeps each `claude -p` / `cswap run` Bash command a session runs (`Conversation.spawns`, text normalised by `spawnText`), and the parent is the session whose command holds the child's first prompt within 10 minutes before it began (2 for a prompt under 20 characters), the closest in time; found once and cached in `m.parents`, a miss retried when the list grows. `sortList` nests after sorting: a family sits where its first member landed, so a waiting child brings it up; ^X G groups a family by its top session's folder (`familyCwd`). A child is nested only when its parent is shown
- `pruneFile()` / `pruneStream()` - Shrink a conversation by dropping duplicate/redundant data (never touches user/assistant lines)
- `runPrune()` - `ccs prune` subcommand driver

## Conventions

- Keys follow Claude Code's prompt: in a text box (the search, the message box, the overlay's box) every Ctrl letter edits text as it does there (^A/^E start/end, ^K/^U kill to end/start, ^W kill word, ^Y paste back, Alt+B/F words; `editKey` adds the ^Y the text box lacks). ccs's own actions are ^X chords, Claude Code's own pattern for app actions (`chordX`, `k = "^x <letter>"`; ^X ^W works as ^X W; an unknown chord does nothing, never edits text), with mnemonic letters: ^X A auto-focus, ^X E edit its name, ^X G group, ^X T table, ^X U user account, ^X W waiting, ^X X prune. Single keys that edit nothing stay single: ^S send, ^R refresh, ^L changelog log, ^O open a link, ^D delete, ^F fork, ? help on an empty search, Tab usage, PgUp/PgDn scroll. A new action is a chord whose letter starts its word; when the letter is taken, pick the action's next clear word. Update the header hints, `shortcuts()`, `--help`, the README and the tests together

- Every interaction must be possible from the keyboard; the mouse (click, wheel) is only ever a shortcut for something a key already does

- Use conventional commits (feat:, fix:, docs:, etc.)
- Run tests before releasing
- Keep it simple: one package, files split by area as listed under Architecture; put new code in the file for its area
